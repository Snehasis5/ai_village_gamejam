How an AI agent's own notes misled it

Over four days, six AI agents built browser games and wrote memory notes for themselves. Comparing the notes in order shows statements losing their conditions, assessments that were never re-checked, and information from another team entering memory.

Background

How agent memory works

When its context fills up, an agent rewrites a summary note and continues from it

An agent's context window cannot hold four days of work. When it fills up, the agent writes a summary of what it needs to keep: the project, its role, and anything to avoid. It then continues from that summary alone. Anything left out of the summary is lost to the agent; anything copied into it is treated as known.

The dataset keeps every version of these notes. This page compares all — of them in order and follows individual lines from one version to the next.

Finding 1 · conditions dropped

A statement loses its condition and becomes incorrect

Two Fable agents recorded observations that were true only in a specific situation. Later versions of the note kept the observation but dropped the situation.

Finding 2 · not re-checked

One review of the other team, repeated in — notes

On Thursday afternoon, a Fable agent looked at Team Sol's code repository and reported back. All three Fable agents copied the conclusion into memory and planned Friday's work around it.

Our scope/atmosphere advantage looks real → Friday = pure polish + reliability.Fable Agent 3 · Thu 4:40 pm

No one checked again. Team Sol's own notes had already listed six enemy types and a boss on Wednesday:

Team differences

The same task produced different kinds of notes

Team Sol's notes focus on process: release versions, code-review results and explicit rules. Team Fable's notes focus on people: what each teammate shipped, what the human organisers said and what the other team was doing. Both teams added more and more lines telling themselves not to repeat messages as the week went on.

Why it matters

Agents on long tasks rely on notes they write themselves

Long-running agents need memory, and here memory is a series of summaries. These notes show three ways a summary can go wrong. None of them is visible by reading a single note.

  1. Dropped conditions. A statement that was true only in a test becomes a general statement.
  2. No re-checking. A conclusion reached once is copied forward without being verified, and it shapes later plans.
  3. Outside information. Shared tools can bring in another agent's context, and the warning about it loses detail each time it is rewritten.
